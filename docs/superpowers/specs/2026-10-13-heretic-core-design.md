## 1. Цель и рамки

Перенести антагониста Heretic из SS13 (tgstation / Paradise) в Space Stories SS14.

- Код пишется **с нуля**. Реализации Goob Station и ADT — только образец (AGPL-3.0 несовместима с лицензией Space Stories).
- Баланс по **Paradise** (MRP), механики сверяются с tg.
- Спрайты и звуки — CC-BY-SA 3.0/4.0, присылает команда; до этого заглушки из существующих текстур.
- Все правила [coding-standards.md](../../../coding-standards.md) обязательны.

## 2. Как Еретик попадает в раунд

- Отдельное игровое правило `STHeretic` (сущность `BaseGameRule` + `StoriesHereticRuleComponent` + `AntagSelection`).
- `minPlayers: 30`, `LinearAntagCount` с `playerRatio: 24`, диапазон 1–3. Повторяет tg: 30 игроков минимум, «чтобы было из кого выбирать жертв».
- Режим `gamePreset` `STHeretic` (алиас `heretic`, `showInVote: true`): `STHeretic` + `SubGamemodesRule` + `CalmStationEventScheduler` + `MeteorSwarmScheduler` + `BasicRoundstartVariation` (как у Тенеморфа).
- Вес в `STSecret`: `STHeretic: 0.05`.
- `antagSpecifier` `STHereticSpecifier` наследует `BaseTraitor` (то есть `RestrictedAntag`: без командования, СБ, боргов, ИИ, интернов, тюрьмы, ЦК).
- Прототип `antag` `STHeretic`: `setPreference: true`, требование `OverallPlaytimeRequirement: 5h` (как у других антагонистов форка), `guides: [ STHeretic ]`.
- Роль разума `STMindRoleHeretic`: `exclusiveAntag: true`, `roleType: SoloAntagonist`.

## 3. Модель данных

Новых видов прототипов нет. Все данные — прототипы сущностей с компонентами.

### 3.1 Знание: `StoriesHereticKnowledgeComponent` (Shared)

Прототипы `STHereticKnowledge*`, абстрактный родитель `STHereticKnowledgeBase`. Имя и описание берутся из локализации сущности.

| Поле | Тип | Смысл |
|---|---|---|
| `Cost` | `int` | Цена в очках |
| `Path` | `ProtoId<TagPrototype>?` | Путь (`STHereticPathAsh`); `null` — общее знание |
| `Stage` | `int` | Ступень (строка в дереве) |
| `Requires` | `List<EntProtoId>` | Нужно изучить хотя бы одно из них (ИЛИ) |
| `ChoosesPath` | `bool` | Изучение выбирает путь и закрывает остальные корни |
| `Starting` | `bool` | Выдаётся бесплатно на старте |
| `Ascension` | `bool` | Требует выполненных целей и `CanAscend` |
| `Actions` | `List<EntProtoId>` | Выдаваемые действия |
| `Rituals` | `List<EntProtoId>` | Открываемые рецепты |
| `AddComponents` | `ComponentRegistry` | Компоненты на еретика (улучшения хватки, метки, пассивы) |

### 3.2 Ритуал: `StoriesHereticRitualComponent` (Shared)

Прототипы `STHereticRitual*`.

| Поле | Тип | Смысл |
|---|---|---|
| `Ingredients` | `List<StoriesHereticIngredient>` | `{ whitelist?: EntityWhitelist, prototypes?: List<EntProtoId>, organCategory?: ProtoId<OrganCategoryPrototype>, amount: int, consume: bool }`; предмет подходит, если совпало хотя бы одно из заданных условий |
| `Results` | `List<EntProtoId>` | Что появится на руне |
| `Limit` | `int?` | Лимит одновременно существующих результатов (клинки: 3) |
| `Effect` | `StoriesHereticRitualEffect` | `None`, `Sacrifice`, `Knowledge`, `FeastOfOwls`, `RerollTargets`, `Ascension` |

Ритуалы с эффектом выполняют свои системы через событие `StoriesHereticRitualPerformedEvent` (`record struct`, `[ByRefEvent]`, поле `Handled`).

### 3.3 Еретик: `StoriesHereticComponent` (Shared, networked, `SessionSpecific`)

`Points` (int), `Path` (тег пути или `null`), `Knowledge` (`HashSet<EntProtoId>`), `Rituals` (`HashSet<EntProtoId>`), `Targets` (`List<NetEntity>`), `SacrificeCount`, `HeadSacrificeCount`, `Ascended`, `CanAscend`, `NextPassivePoint` (TimeSpan), `PassivePointInterval` (20 мин), `KnowledgeRitualUsed`, `LimitedResults` (словарь «ритуал → существующие сущности»).

Поведение вешается отдельными маленькими компонентами, которые знания добавляют через `AddComponents`. Например: `StoriesHereticGraspAshComponent`, `StoriesHereticMarkAshComponent`.

## 4. Системы

Все системы — `Stories*`. Зависимости вверху по алфавиту без слова «System». Подписки идут через `Entity<T>`, методы `On*`. Константы хранятся в полях компонентов. ID прототипов в коде — `static readonly ProtoId<T>` / `EntProtoId`. Поиск через `EntityLookupSystem` — с полями `HashSet`.

| Система | Сборка | Ответственность |
|---|---|---|
| `StoriesHereticSystem` (partial: `.Points`, `.Knowledge`, `.Focus`) | Shared | **Единственный** владелец `StoriesHereticComponent` (`[Access]`): инициализация, стартовые знания, пассивные очки (проверка по времени только у сущностей с `StoriesHereticComponent`, их единицы), `CanLearn` / `TryLearn`, выдача наград, BUI-сообщение покупки, проверка фокуса, публичное API для остальных систем (`AddPoints`, `RegisterSacrifice`, `SetTargets`, `TrackLimitedResult` и т.д.) |
| `StoriesHereticRitualSystem` | Shared | Рисование и удаление руны, сбор предметов на руне, сопоставление рецептов, выдача результатов, лимиты |
| `StoriesHereticInfluenceSystem` | Shared + Client | Влияния: сбор, превращение в «разорванную реальность»; на клиенте видимость только для еретика |
| `StoriesHereticSacrificeSystem` | Server | Цели, ритуал жертвы, Теневой мир, возврат, `StoriesHereticSacrificedComponent` |
| `StoriesHereticLivingHeartSystem` | Shared | Действие: направление и дистанция до цели плюс звук сердцебиения в радиусе |
| `StoriesHereticGraspSystem` | Shared | Хватка Мансуса: базовый эффект, улучшения через события, метки, блокировка святыми |
| `StoriesHereticAshSystem` | Server | Рывок, метка, извержение вулкана, огненный клинок, перерождение, способности Вознесения (`FlammableSystem` есть только на сервере) |
| `StoriesHereticRuleSystem` | Server | Правило: влияния на старте, цели, итог раунда |
| `StoriesHereticKnowledgeUISystem` | Client | Окно дерева |

## 5. Механики ядра

### 5.1 Очки

| Источник | Очки |
|---|---|
| Старт (как в tg: сразу хватает на выбор пути) | 1 |
| Влияние | 1 (2 с раскрытым Кодексом) |
| Жертва | 2 (глава отдела: 3) |
| Пассивно | 1 каждые 20 минут |
| Ритуал знаний | 4, один раз |
| Пир сов | 5, ставит `CanAscend = false` |

Все числа задаются в YAML.

**Ритуал знаний:** при появлении еретика из прототипа датасета `STHereticKnowledgeRitualTags` (теги `Knife`, `Candle`, `Book`, `GlassShard`, `Matchstick`, `Write`, `Sheet`) выбираются 4 случайных разных тега и сохраняются в `StoriesHereticComponent.KnowledgeRitualTags`. Рецепт: по одному предмету с каждым тегом. Подсказка с нужными тегами видна в окне дерева.

### 5.2 Стартовые знания (бесплатно)

- Рассвет (Break of Dawn) → Хватка Мансуса.
- Сердцебиение Мансуса → ритуал жертвоприношения.
- Живое сердце.
- Руны: умение рисовать.
- Рецепты Янтарного фокуса и Кодекса.
- Ритуал знаний, Пир сов, Неумолимое сердцебиение (переброс целей).

### 5.3 Влияния

- При старте правила появляется `8 + 2 × число еретиков` влияний (`STHereticInfluence`) на случайных плитках станции без стен, с атмосферой, вне космоса.
- Видимы и интерактивны только для еретиков: клиентская система скрывает спрайт у остальных, на сервере проверка при взаимодействии.
- Сбор: пустая рука, do-after 5 с → очки, влияние заменяется на `STHereticPiercedReality`.
- Разорванная реальность видна всем. Осмотр не-еретиком отнимает 20 выносливости и вызывает галлюцинации на 5 с (урона мозгу в SS14 нет). Касание с шансом 1/4 наносит 20 урона `Slash`.

### 5.4 Руны

- Действие «Начертить руну» (`WorldTargetAction`) с предметом с тегом `Write` в активной руке, по свободной плитке пола (без препятствий 3×3) → do-after 10 с (с раскрытым Кодексом 10/3 с) → `STHereticRune`. Отдельное действие вместо «клика ручкой» нужно потому, что подписываться на взаимодействие всех ручек в игре нельзя.
- Хватка Мансуса или Кодекс в руке по руне → удаление.
- Активация: пустая рука по руне. Система собирает сущности в радиусе руны и проверяет **известные** рецепты по порядку. Первый подходящий выполняется, ингредиенты с `consume: true` удаляются. Если ничего не подошло, появляется всплывающее сообщение со списком того, чего не хватает для ближайшего рецепта.
- Руной может пользоваться любой еретик.

### 5.5 Жертвоприношение и цели

- На старте 5 целей: 1 глава, 1 СБ, 1 из отдела еретика, 2 случайных члена экипажа. Если кандидатов нет, слот добирается случайным членом экипажа.
- Цели можно перебросить ритуалом «Неумолимое сердцебиение»: в SS13 это колокольчик, книга и комбинезон. В SS14 нет колокольчика, поэтому `FoodPoppy` + тег `Book` + любая одежда (компонент `Clothing`) → 5 новых целей.
- Жертва должна лежать на руне и быть в критическом состоянии, мёртвой, в наручниках или спящей. Еретик активирует руну.
- Результат:
  1. Очки, `SacrificeCount++`, у глав также `HeadSacrificeCount++`. Цель удаляется из списка.
  2. Жертва полностью лечится и оживает (`Rejuvenate`). Если разума нет, на руне остаётся «грязь» (декаль крови), очки всё равно засчитываются.
  3. Жертва переносится в Теневой мир на 60 с, затем возвращается на случайную безопасную плитку станции.
  4. Жертва получает `StoriesHereticSacrificedComponent`: сообщение «вы не помните, кто это сделал». Когда она атакует еретика с фокусом или еретик с фокусом атакует её, жертва сбивается с ног на 3 с и получает 15 урона `Blunt`.
- Не-цель принести в жертву нельзя: появляется всплывающее сообщение.

### 5.6 Теневой мир

- Отдельная карта, которая создаётся **в коде** при первой жертве за раунд: тёмная площадка 9×9 из плитки, атмосфера, приглушённый свет, вокруг пустота. Мир кэшируется до конца раунда.
- Каждая жертва попадает на свою площадку (смещение по X), чтобы жертвы не встречались.
- Поле `ShadowRealmMap` (`ResPath?`) в компоненте правила: если оно задано, загружается готовая карта от маппера, без правок кода.
- Пока жертва там, она каждые 5 с получает 4 урона `Cold` и галлюцинации (`SeeingRainbows`).

### 5.7 Живое сердце

- Каждое нажатие действия переключает на следующую живую цель из списка и показывает всплывающее сообщение: имя цели, направление (8 сторон) и примерная дистанция (рядом / средне / далеко / на другой карте).
- Звук сердцебиения слышен в радиусе 5 тайлов. Это не скрыто.
- Перезарядка 10 с.

### 5.8 Хватка Мансуса

- Действие с выбором цели (`EntityTargetAction`, дальность 1.5 — как удар рукой). Перезарядка 10 с. В SS13 это предмет в руке; у нас поведение то же, но без неснимаемого предмета.
- Удар по существу: 80 урона выносливости, сбивание с ног на 2 с, невнятная речь 5 с.
- Если цель святая (`SharedHolySystem.IsHoly`) или в руках у неё нуль-жезл (предмет с `HolyComponent`): эффект блокируется, перезарядка тратится, появляется сообщение.
- Знания пути добавляют эффекты через событие `StoriesHereticGraspHitEvent` (`[ByRefEvent]`): ослепление, наложение метки.
- Применение по руне удаляет руну.

### 5.9 Фокус

- `StoriesHereticFocusComponent` на предметах. Действие с `StoriesHereticRequiresFocusComponent` проверяет фокус в слотах шеи, глаз или в руках у раскрытого Кодекса. Без фокуса: отказ и сообщение.
- После Вознесения фокус не нужен.
- Янтарный фокус: `SheetGlass` + орган категории `Eyes` → `STHereticAmberFocus` (слот шеи).
- Кодекс: предмет с тегом `Book` + предмет с тегом `Write` + шкура или кожа (`prototypes`: `MaterialHideBear`, `MaterialHideCorgi`, `ClothingHandsGlovesLeather`) → `STHereticCodexCicatrix`. Раскрывается действием в руке.

### 5.10 Клинок еретика

- Рецепт пути (у Ash: нож + спичка или зажигалка) → `STHereticBladeAsh`, не больше 3 одновременно.
- Удар по помеченной цели снимает метку и вызывает её эффект.
- Сломать клинок в руке (действие «использовать в руке», do-after 1 с) → телепорт на случайную безопасную плитку в 10–20 тайлах. Клинок уничтожается.

| Ст. | Знание | Цена | Эффект |

| 1 | Секрет Ночного дозорного | 1 | Выбор пути; рецепт клинка Ash: тег `Knife` + тег `Matchstick` или `Lighter` |
| 2 | Хватка Пепла | 1 | Хватка ослепляет на 5 с |

| 3 | Пепельные глаза (побочное) | 1 | Рецепт: тег `GlassShard` + тег `Candle` + орган `Eyes` → повязка на глаза с тепловым зрением (Vision из форка; в SS13 это амулет, но зрение форка не работает из слота шеи). Служит фокусом |

| 5 | Маска безумия (побочное) | 1 | Рецепт: `ClothingMaskGas` / `ClothingMaskBreath` / `ClothingMaskSterile` + 4 × тег `Candle` + `Stunbaton` + орган `Liver` → маска; не-еретики в радиусе 5 раз в 2 с получают 5 урона выносливости и `SeeingRainbows` |
| 6 | Огненный клинок | 2 | Клинок Ash при ударе добавляет 1 огненный стак |
| 7 | Перерождение Дозорного | 1 | Все горящие живые в радиусе 7: еретик лечит по 10 каждого типа урона за цель, тушится; критическая цель добивается. Перезарядка 60 с. Требует фокус |
| 8 | Обряд Повелителя пепла (Вознесение) | 2 | Требует выполненных целей. Ритуал: 3 трупа, каждый горит или имеет урон `Heat` ≥ 100 |

### Вознесение Ash

- Иммунитет: к давлению, температуре, огню (`PressureImmunity`, модификатор урона Heat ×0, Barotrauma off).
- **Огненное кольцо:** 60 с еретик окружён огнём, все в радиусе 2 каждые 0.5 с получают 2 стака.
- **Огненная волна:** конус 7 тайлов, 20 `Heat` и 5 стаков.
- Глобальное объявление и звук, флаг `Ascended`. Фокус больше не нужен.
- Вознесение — это победа еретика в итогах раунда. Раунд **не** заканчивается (в отличие от Тенеморфа), как в SS13.

## 7. Окно дерева знаний

- Действие `STActionHereticKnowledge` открывает BUI `StoriesHereticKnowledgeUiKey` на сущности еретика.
- XAML-окно `StoriesHereticKnowledgeWindow`:
  - сверху очки и выбранный путь;
  - колонки: «Общие» + по колонке на путь (в подпроекте 1 только Ash; остальные пути появятся в своих подпроектах без правок кода окна);
  - строки — `Stage`; узлы — кнопки с иконкой, названием и ценой; связи `Requires` — линии;
  - состояния узла: изучено / доступно / закрыто (с подсказкой причины).
- Данные окно берёт из `StoriesHereticComponent` и прототипов знаний. Отдельного BUI-состояния нет. Обновление через `AfterAutoHandleStateEvent` в `try/catch` с логированием.
- Покупка: `StoriesHereticLearnMessage(EntProtoId)` → сервер вызывает `TryLearn`.
- Бизнес-логика в BUI; `.xaml.cs` только рисует.

## 8. Итоги раунда и цели

- Цели (сущности `STHereticObjective*`): «Изучить N знаний» (N=6, считаются только купленные, без стартовых), «Принести в жертву N целей» (N=4), «Принести в жертву главу» (1). Прогресс берётся из `StoriesHereticComponent` через собственный компонент условия `StoriesHereticObjectiveConditionComponent` (тип: знания / жертвы / главы и требуемое число).
- Итоги: список еретиков (имя, игрок, путь, число знаний и жертв, вознёсся ли). Победа = вознёсся.

## 9. Взаимодействие с другими системами

- **Святое (форк):** Хватка не действует на святых и носителей `Holy`-предметов. Сам еретик **не** `Unholy`: это обычный человек.
- **Mindshield:** не влияет.
- **Другие антагонисты:** роль исключительная, двойных антагонистов нет.
- **Влияния** появляются только на сетках станции (`StationMember`), на плитках пола без сущностей с коллизией `Impassable`.

## 12. Ошибки и крайние случаи

- Еретик умер: компонент остаётся на теле, после реанимации всё работает. Если разум переходит в **другое** тело (клонирование, борг), силы остаются со старым телом, а роль антагониста — с разумом (как у Генокрада в апстриме). Перенос сил в новое тело вне рамок подпроекта 1.
- Руна удалена во время ритуала: ритуал отменяется, ингредиенты не тратятся.
- Цель жертвоприношения удалена или покинула раунд: слот пустой, ритуал «Неумолимое сердцебиение» добирает цели.
- Теневой мир: если жертва умерла там, она возвращается трупом в том же порядке. Если удалена — запись снимается.
- Лимит клинков: удалённые или сломанные клинки удаляются из `LimitedResults` (подписка на удаление).
- Клиент получает данные только своего еретика (`SessionSpecific`).

## 13. Тестирование

Интеграционные тесты в `Content.IntegrationTests/Tests/_Stories/Heretic/`:
1. `HereticRuleTest`: правило выдаёт роль, стартовые знания и цели (по образцу `TraitorRuleTest`).
2. `HereticKnowledgeTest`: покупка списывает очки; без `Requires` не покупается; выбор пути закрывает другие корни; Вознесение без целей недоступно.
3. `HereticRitualTest`: рецепт клинка на руне создаёт клинок и тратит ингредиенты; лимит 3 соблюдается.
4. `HereticSacrificeTest`: жертва-цель даёт очки и уходит в Теневой мир; не-цель не принимается.

Плюс `Content.YAMLLinter` и полный `dotnet build` без новых предупреждений.
